# 项目 QMT 内置 Python 策略编写手册

项目维护文档，版本 2026-10-15.1。适用目标：券商 QMT 客户端内置 Python。不是迅投官方手册，也不适用于 MiniQMT 外部 xtquant 脚本。

## 1. 查资料并确定策略含义

先搜索本地库，阅读本手册、生命周期及会用到的接口正文。搜索摘要只能定位，分页资料需读完。记录官方来源、核对日期、资料包版本和内容哈希；资料不含某接口时查官方原文或券商帮助，不猜参数。

核对股票范围、周期、信号判断时点、仓位、退出条件和运行模式。说明默认假设；“均线上穿”必须比较前后两期关系，不能改成“价格高于均线”。历史动态股票池需要当时成分，不能用当前成分冒充历史。

## 2. 组织源码与环境

参数集中在文件顶部。保留 init / handlebar，按需求增加 after_init / stop / 回调。内置上下文方法与终端全局函数不能混成 xtquant 外部接口。版本未知时使用 Python 3.6 兼容语法，明确第三方依赖；不假设用户有 talib。

`C.do_back_test` 是回测布尔属性，不能写成 `C.is_back_test` 或调用方法。缺少属性时停止依赖该模式的逻辑并说明，不能把未知模式当回测。默认不启用实盘委托；账号是参数，不收集密码或私钥。

源码在项目中保存为 UTF-8，导出支持 GBK / UTF-8，声明与字节一致。中文注释与 GBK 不支持的字符需在导出前检查。

## 3. 行情、时序和前视检查

历史请求指定当前 bar 对应 end_time；回测用已下载本地数据，通常 subscribe=False。明确 fields、period、count、dividend_type、fill_data，不让跟随主图的隐式参数改变策略含义。

本项目的日线信号示例在返回序列中排除最后一行，只依据上一根已完成 bar 判断。因此至少滞后一根主图 bar；最后一天信号需要后续主图 bar 才会输出，不声称是当日收盘立即触发。跨证券缺失数据要分别核对日期，不能把另一只股票更早的尾行冒充相同决策日。

预热不足、空表、NaN、无穷、停牌或无成交时跳过并报告。信号窗口只用决策时点之前的数据；突破比较排除信号当天。复权会影响历史值，回测还应说明点时复权的局限；不能用未来价格填补历史缺口。

## 4. 委托、仓位和重复触发

为每个 passorder 参数给出来源和单位。查询实际可用资金、可卖数量和未成交委托；股票 T+1、品种最小交易单位、涨跌幅、费用与权限分别核对。委托成功提交不等于成交；状态以查询及回报为准。

信号日志可用全局对象按证券、决策时间和方向去重。ContextInfo 自定义属性可能回滚；进程内集合在重启后丢失，不能当成实盘订单唯一保障。需要交易状态时还需核对持仓、未成交单、部分成交、撤单、错误与重启恢复。没有这些内容的样例只标为教学草稿。

回测委托样例即使关闭实盘也不等于真实成交模拟完整。说明撮合时点、手续费、滑点、整手约束以及与实际盘口的区别，不能用回测曲线证明可执行性或收益。

## 5. 验证与交付

生成前读取相关文档，生成后静态检查，再导出 .py。静态检查与本地 mock 测试不运行 QMT 客户端，不验证 API 实际可用性、收益或完整无前视。

交付策略解释、参数与默认值、完整源码、下载文件、使用依据和验证边界。每次修改用新文件，不覆盖历史。使用依据引用本轮实际读过的条目及官方链接，不把搜索发现当成已阅读。

客户端验收：确认券商和版本 → 补齐历史数据 → 核对主图及回测参数 → 检查信号日期与重复触发 → 检查异常/空数据/费用/交易单位 → 人工判断后再决定后续使用。工作台本身不连接券商、不运行生成策略。
