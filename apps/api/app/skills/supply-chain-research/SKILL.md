# 产业链研究

用于产业主题扫描、供应链卡点研究和公司产业敞口核验。先解释主题背后的系统变化，再判断哪些层级真正受约束，最后核验哪些公司能从约束中获得可验证的业务收益。结论是研究优先级，不代替交易决策。

## 研究步骤

- **说明系统变化。** 明确需求为何增长、旧有方案哪里受压，以及真正可能限制交付的物理、技术或经济条件。把市场叙事当作待验证假设。
- **拆解价值链。** 按经济和技术差异区分终端需求、系统集成、关键部件、芯片与器件、制造工艺、设备、材料、测试和基础设施等相关层级。按问题需要展开，不为完整而堆砌环节或公司。
- **先排约束层级。** 分别检查供应商集中度、扩产周期、良率与可靠性、客户认证、专有技术、关键材料、交期、替代路线和客户议价能力。区分技术难点、阶段性短缺、准入门槛与持续的供给约束，并判断扩产、替代或需求回落会怎样缓解约束。
- **再核验公司。** 对候选公司确认具体产品及产业链位置，并查证客户或认证、产能、订单、交付、收入敞口和利润贡献。严格区分概念相关、送样或认证、意向订单、正式订单、实际出货和收入确认；没有披露的环节标为未知，不从产业链位置推定公司受益。
- **比较证据和反方解释。** 优先用公司公告、客户或供应商披露、监管文件、原始技术资料和可复算数据。核对日期及原文，同一公告的转载不算独立交叉验证。主动检查扩产提速、技术替代、客户自研、需求放缓、库存、资本开支、份额流失和利润率恶化等反证。
- **排序并设定失效条件。** 把层级优先级与公司优先级分开，解释证据强弱、供应约束距离、公司敞口和主要风险。若讨论估值，只在有可比数据时说明估值和预期已反映多少；产业卡点不等同于股票回报。给出哪些可观察变化会提升、降低或推翻判断。

## 深度控制

按用户的 `research_depth`、问题范围和证据可得性控制工作量。标准研究优先验证最关键的两三个约束和少量最相关公司；深度研究再扩展到相邻层级、潜在替代者、客户或竞争对手交叉核验及量化比较。不要把固定候选公司数或来源数当成完成标准；证据不足时缩小结论并明确缺口，不用低质量材料凑数量。

交付时先给出最值得研究的层级及原因，再给公司优先级、证据链、反方理由、主要风险、下一步核验事项和判断失效条件。简短问题只回答相关部分。遵循主投研 Skill 的原文引用、日期、数据口径和权限边界；缺少证据的公司保留为待核实线索。
