# Codex 研究工作区

日期：2026-09-30。

本轮将对话从条件编辑入口调整为可持续的研究工作区。用户可以先要求阅读资料、比较公司、计算指标或验证假设；Codex 可以使用原生终端和文件工具，在真正运行程序后依据结果继续研究。形成可复用方案和正式筛选是研究中的可选业务动作。

## 输入、计算与交付

每个产品对话使用同一个 Codex thread，并在应用数据库所在目录的 `research/<conversation-id>/work/` 保留工作文件。每个回合导出一份只含报告元数据、完整逐页文本和资讯版本的 SQLite 输入快照，放在相邻的 `inputs/`。快照不包含应用业务表或模型凭证；原始 PDF 和 Parquet 行情通过清单中的路径读取，不复制大型行情。

工作目录中的 `research-inputs.json` 给出 Python、依赖、行情文件指纹、资料快照和成果目录。原生 Codex 使用 `workspace-write`，工作目录外的数据只读；生成程序可以使用已安装的 NumPy、DuckDB、PyArrow、pypdf 等。模型凭证留在运行时环境中，研究 shell 使用核心环境变量和明确的 Python 依赖路径。

研究回合现允许网络访问，可使用已安装的 Playwright 启动独立无头 Chromium/Edge 查阅公开网页，不复用用户浏览器配置文件。Tushare 查询通过 `query_tushare` MCP 工具调用服务端现有中转客户端；密钥不进入研究 shell、工作区清单或工具结果。工具限定只读接口、参数和单次返回行数。外部数据要记录接口、查询时间、口径和可得日期；正式筛选仍以冻结的本地数据为准。

`outputs/` 中的文件会在 Web 的“研究成果”区出现。聊天答复支持 Markdown 表格、代码与成果链接；模型返回的本地成果路径映射到当前对话的下载接口。下载限制目录范围、链接文件与大小；HTML、SVG 等生成内容按附件下载，不在应用源中直接执行。

研究文件跨回合保留，停止或时间预算耗尽后也可继续使用。停止研究会取消当前 Codex 回合并拒绝其迟到业务写入。已经提交的正式筛选是独立后台任务，使用结果区原有的取消操作管理。

Codex 回合和研究计算均进入持久后台任务，不依赖浏览器 HTTP 连接。研究回合由独立 worker lane 消费，研究扫描由计算 lane 消费，因此 Codex 可以启动一个全市场计算并继续读取已提交的检查点。Codex worker 中断时不会自动重放旧回合；服务会将回合标记为中断，保留 thread、工作文件和已提交扫描，后续用户回合可以恢复研究。扫描 worker 中断时，`per_stock` 模式跳过已提交证券继续处理；`cross_sectional` 模式保留完整横截面口径，必要时重新计算。

## 研究工具和正式筛选

研究工具采用独立的 MCP 定义和调用类型（`tool_protocol.py`），不再依赖旧模型客户端的函数工具类型或严格 schema 规则。`inputSchema` 保留 Pydantic 的结构化对象、可选字段和默认值；Tushare 的 `params` 直接传对象。读写与外部访问标记在工具注册处声明，服务端仍执行参数校验、回合状态检查和业务授权。

相对时间请求（如“最近/近期/近 N 个交易日/最新”）在保存新的筛选任务修订时，会将截止日设为本地行情文件实际可用的最新交易日。没有日期意图的纯条件修改继续沿用原截止日；明确日期由用户指定。开放研究不会自动改写已保存的筛选任务或其历史运行，因此右侧显示旧方案时，需区分它与本轮研究答复使用的数据日期。

原生文件和 Python 工具承担自主探索；以下 MCP 工具提供业务集成：

| 工具 | 行为 |
| --- | --- |
| `search_research_sources` / `read_research_source` | 无需先创建筛选条件即可发现和阅读完整资料；可显式指定历史截止日，资讯发现使用当时已可用的版本。 |
| `query_tushare` | 使用服务端配置的中转客户端查询限定范围的行情、交易日历、财务及资讯接口；不返回凭证。 |
| `discover_research_data` | 返回本回合实际 Parquet 字段/类型、日期范围、单位标记、SQLite 快照表结构和路径；无需先建立筛选任务。 |
| `get_research_state` / `propose_screening_task` | 读取、创建和修改可执行方案。开放研究无需先调用这些工具。 |
| `preview_screening_program` | 运行当前 Python 条件的最多 20 只样本，返回实际结果或程序错误，允许 Codex 修复后重试；不创建正式运行。 |
| `execute_screening_task` | 核验用户原话中的正式执行授权，在同一研究回合内创建版本化运行。相同回合、相同修订重复提交返回原运行。 |
| `read_screening_run` | 等待最多 20 秒并读取进度、错误、覆盖和逐股依据，供同一 Codex 会话继续分析。只读取该对话固定的历史运行。 |
| `save_screening_plan` | 保存可复用方案，返回资产 ID 和版本；保存本身不执行。 |
| `start_research_scan` / `read_research_scan` / `cancel_research_scan` | 启动、读取和停止只读研究扫描。默认 `cross_sectional` 将冻结的完整证券范围一次传入程序，适合排名/分位数；独立逐股计算可选 `per_stock`，结果按批次持久化并可恢复。扫描可导出 CSV，不创建筛选修订、正式运行或观察池记录。 |

原有前端执行接口仍可承接 `authorize_screening_execution` 的授权。服务端对同一运行请求保持幂等。普通研究计算属于用户研究请求的必要步骤，不要求额外的正式筛选授权；“只保存”“只讨论”和明确否定执行仍然不会触发正式筛选。外部 Tushare 查询的 `items` 是提示词预览，完整接口页保存为 `outputs/` 中的 artifact，Codex 应按接口分页并核对单位、复权和可得日期。

界面的确认按钮直接调用 `/conversations/{id}/turns/{turn_id}/execute`，发送 `action=button`、当前任务 `revision` 和本次点击的 `request_id`。按钮本身是授权，不要求之前的用户消息含执行关键词，也不追加用户消息或启动 Codex 回合。相同请求重试复用运行，成功后再次点击可创建新运行；过期版本、未完成回合、不完整方案和冻结过程中行情变化仍被拒绝。范围与日期由前端延迟 400 毫秒自动保存，沿用原事务接口，不自动执行；载入方案不会触发默认值写入，未发送草稿保留。

## 配置

`config.ini` 的 `[app] reasoning_effort` 现在会传给 Codex 配置及每个原生回合，包括恢复的 thread。未配置时使用 `high`；保留现有模型，不自动更换。当前本地配置的 `gpt-6-luna / max` 已用于真实验收。

`[research]` 支持：

- `mode`：新对话默认使用 `research`；也可选 `screening` 或 `advanced`，环境变量为 `LLMR_RESEARCH_MODE`。模式随对话保存在数据库中，可在输入区切换；运行中的回合不允许改模式。
- `turn_timeout_seconds`：默认 1200 秒，可配置 30–7200 秒；到期中断当前研究并保留文件。
- `max_tool_calls`：默认 0，移除统一的 12 次限制；可显式设置业务工具调用预算。
- `max_output_file_bytes`：默认 50 MiB，控制单个成果下载大小。

对应环境变量为 `LLMR_RESEARCH_` 加大写配置名。调用预算适用于 MCP 业务工具；原生文件/终端操作由 Codex 执行，整个回合受时间预算约束。应用尚未实现按实际模型费用的硬配额。

研究模式优先证据与探索计算，筛选模式优先可复用方案和实际筛选结果；两者使用配置的基础预算。深度研究（`advanced`）将回合时间提高到至少 3600 秒，单个成果预算提高到至少 200 MiB。模式与有效预算传给 Codex；所有模式共享研究工作目录、网络与原生计算能力，业务写入继续走专用接口。

## 实际范围

这次恢复了开放研究、实际编程验证和同回合筛选反馈。正式批量筛选的研报/资讯条件仍复用 `evidence_analysis.py` 的受限资料判断执行器；目录整理等独立模型服务也保留。开放研究不再必须经过这些执行器，可由同一 Codex 直接阅读原始资料、交叉比较并交付研究成果。不能将本轮描述为所有独立模型调用都已退役。

这是当前本地部署的研究执行环境。`workspace-write` 提供写入边界，默认读取权限和现有单用户服务不构成多租户隔离；公开 Web 服务的用户隔离、配额和部署环境仍需单独实现。历史日期、复权与单位等数据质量要求继续适用。
