# 第四交付包：财务、披露与研究证据连接

交付日期：2026-10-21。范围为现有十家试点公司的研究工作流，继续使用已取得的普通 Tushare 财务数据和手动归档的原始披露。

## 使用入口

- 研究项目 → 选择“公司研究对象” → “标准财务与指标计算” → 某期“查看计算依据”。
- 在输入来源下查看原始值、单位、公告日期、首次观察日期、范围和源版本；“原文关联与独立数字依据”可打开相关原件、定位 PDF 物理页、保存文档关联或人工数值核对。
- “保存独立数字依据”生成可独立打开的引用页面及标识。复制链接到研究答复，或在笔记判断中附上标识；无需保留原聊天才能核对这个数字。
- 研究项目 → “同业对比” → “标准财务同业对比”，选择 3–5 家项目关联公司、统一截止日、指标及期间/版本口径。保存后可重开历史比较，也可逐格取得数字依据。
- 公司研究 → “资料变化”，手动检查新披露、源值修订、派生指标变化、口径版本变化和原文核对冲突；相关旧笔记与数字引用可进入复核。

现有六个 / 命令继续可用。/财务 直接复用新的数字依据区，/披露 继续使用同一归档与阅读器。

## 原文关联与数值核对

原文核对记录独立于财务事实，不回写或覆盖 Tushare 原始值。

1. **仅关联文档**：分类已确认且公司、报告期相符。即使定位了原页，也不自动声称数值已核验。
2. **数值已核对**：用户明确确认期间列、单位、币种和合并范围，提交物理页、精确原文摘录、原单元格数字及列说明。服务器校验完整数字词元、原始小数精度、单位换算和 Decimal 舍入容差。
3. **数值冲突**：在同样的检查下，两数差异超过原文最后一位精度的一半。保留双方数值、差异、容差及原 PDF，不自动改数。

只有对应报告期的完整定期报告可用于数值核对；摘要、更正说明、未知合并范围及缺失源值不能据此标为已核对。跨期比较列和更正说明可以保存为披露原文证据，尚不自动替换标准财务事实。

同一文件的重新核对保留旧记录；同一逻辑披露的新文件版本替代旧文件的当前核对状态。分类修改会提示复核。不同披露系列之间的冲突不会自动消失。核对请求带请求标识，网络重试复用原结果，避免重复发布。

## 冻结、截止日与引用

- 计算保留请求、源事实/记录、精确原始字段、单位、公式及标准化版本；金额用元计算、页面按亿元展示。期末余额显示实际时点口径，不把余额说成 TTM 流量。
- 独立数字依据冻结该点全部输入以及当时的原文关联/核对状态。之后同步财务、重新核对或修改披露分类，不会改写旧依据。
- “当时可验证口径”同时约束公开日期与平台首次观察/归档日期；截止日之后才归档的原件不进入该查询的数字证据。“最新修订口径”允许取得后来的版本，明确保留历史局限。
- 笔记中的严格历史判断再次检查数字、输入及关联原件的公司与可得日期，不能倒填后取得的证据。
- 新研究回合的 SQLite 输入快照包含财务源记录、事实、观察记录、计算、原文关联、披露版本/分类/页文本和已保存的数字依据。回合中出现的新修订不能替换冻结输入；旧回合缺少这些表时要求开启新回合，不偷偷读当前库。
- 已保存的旧数字依据可在后续回合按标识读取；前提是该依据已经存在于后续回合的输入快照。
- 答复来源区区分财务、披露、研报和资讯。分享快照及 PDF 带上有界的冻结数字/原文摘录、哈希与来源标识；不在导出时重新计算。

这保证平台自身的版本可追溯性，不声称已恢复供应商尚未提供的完整历史修订链。原文人工数值核对也不会改变这一边界。

## 研究工具与资料选择

新增 get_company_financials、read_financial_evidence、compare_company_financials、search_disclosures、read_disclosure。工具读取当前回合冻结资料，强制公司和截止日范围，按需分页返回；全量原始输入留在独立依据中，不重复塞入模型上下文。

资料包按报告期、定期报告类型、研究问题和章节相关性选择披露，预留原始披露位置；合并及公司报表等章节标题支持检索。资料覆盖会明确呈现，未找到材料不会解释成公司未披露。

变化检查使用源值、公式/标准化合同和原文核对的指纹，单纯再次观察同一记录不会制造财务变化；滚动展示年限变化不会误报“财务消失”。对依赖被修订输入的单季/TTM 数字一并找出旧引用与笔记。变化提示用于复核，不自动改写投资判断。

- GET /api/v1/financial-data/comparisons、/comparisons/{id}
