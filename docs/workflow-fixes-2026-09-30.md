# 工作流问题修复 · 2026-09-30

本次修复工作流审查确认的五项问题，基于移除旧对话 planner 后的 Codex 单入口实现。

| 问题 | 修复后的行为 |
| --- | --- |
| 条件修订后发生异常，对话一直运行 | 失败终态独立于初始条件版本写入，保留已提交修订并清除未消费执行授权；用户可以继续对话。 |
| 进程中断后回合无法恢复 | 对话处理期间每 15 秒续约，90 秒无心跳的 running 回合会在启动或读取时回收为失败；迟到回复、条件修订和授权不能重新写入。 |
| OR 被默认转换成 AND | 仅对 AND/OR/NOT 等明确等价别名进行规范化；未知运算符、缺失逻辑、冲突字段和损坏子节点会拒绝保存。 |
| 否定要求通过执行授权 | 服务端检查当前用户原话，拒绝明确否定、只保存、讨论、询问和引用的指令；明确撤销在消息入库时即清除既有待执行授权。含糊表述可使用页面执行按钮确认。 |
| 刷新后不再跟踪进度 | 当前持久化回合状态驱动轮询，页面恢复后自动续接，终态停止轮询。已授权且尚未提交的筛选会续接执行；本页面复用同一提交 Promise，服务端仍以回合 ID 保证幂等。 |
| 对话保存不进入方案库 | `propose_screening_task` 只报告条件修订；新增 `save_screening_plan` 与 `list_saved_screening_tasks`，使用页面同一方案库，返回资产 ID、版本和名称。保存不授予执行权限。 |

保存请求通过新迁移 `019_saved_task_requests.sql` 持久记录请求与资产版本。页面保存和 MCP 保存复用同一业务服务；丢失响应后的相同请求返回原资产，使用同一请求 ID 更换内容会报冲突。迁移由应用启动时自动执行，不重写既有方案。

新增回归用例覆盖条件变更后运行时失败、失联回合回收、迟到写入拒绝、OR/NOT 与 unknown 语义、非法逻辑拒绝、否定及讨论授权、撤销此前授权、保存重试及冲突、从对话保存后在另一对话复用，以及页面恢复后的进度与授权执行续接。
