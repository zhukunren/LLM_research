# 多用户 Web 改造方案

日期：2026 年 10 月 12 日。状态：第一批与本机 gVisor 严格验收已通过；第二批标准 OIDC、个人工作空间和任务权限已完成并通过回归；第三至六批待实施。

保留当前 `openai-codex` Python SDK、FastAPI 和 React。将现有本地工作台改为有身份认证的数据服务，以及独立的代理和计算执行服务。用户通过网页研究、上传材料、保存成果和运行选股；生产应用源码、依赖、发布产物和配置只由发布系统管理。

源码保护由发布目录的操作系统权限、只读镜像和执行环境隔离共同实现。即使代理完全听从恶意提示，或生成程序能运行任意 Python，也只能写自己的任务工作区。开发者的本地仓库仍可正常开发；生产服务不运行在该可写仓库中。网页 JavaScript 会正常交付到浏览器，用户改变本地浏览器内容不能改变服务端发布版本。

第一批和 gVisor 的本机严格验证记录见 [存储拆分与 SDK 验证](D:/项目/LLM_research/docs/phase1-storage-and-sandbox.md)。第二批实现说明见 [用户权限改造](D:/项目/LLM_research/docs/phase2-user-permissions.md)。生产数据库、执行网关、统一计算沙箱及部署验收仍待实施。以下阶段全部验收后，才开放给外部用户。保护范围包括应用用户、代理、上传内容及生成代码；系统管理员和发布身份属于可信运维边界。

## 一 已确定的架构选择

- 继续使用 Python SDK；它通过 JSON-RPC 控制本地 app-server，无需重写客户端协议。[官方 SDK 文档](https://learn.chatgpt.com/docs/codex-sdk)
- 生产部署采用 Linux，业务服务与执行节点分开。执行节点使用 gVisor 的 `runsc` 运行隔离容器；每个活跃研究任务或计算任务单独创建环境。[gVisor 官方说明](https://gvisor.dev/docs/)
- 生产业务数据库采用 PostgreSQL。服务层逐资源授权，加上数据库行级安全策略；SQLite 保留用于本地开发和研究输入快照。
- 第一版每位用户有独立的个人租户。数据模型预留团队成员和显式共享，但第一版不自动把同一租户内所有用户的数据互相开放。
- 私有附件、资料和成果进入私有对象存储；公共行情可以共享只读数据。目录、对象键和数据库字段都有归属，最终权限由服务端校验。
- 代理仅持有本次任务的短期凭证，通过业务工具网关和模型网关获得所需能力。数据库、模型供应商、行情供应商和对象存储的长期密钥留在可信服务。

这些是本项目的实施选择，不是 SDK 自动提供的多用户能力。

## 三 源码不可写的部署结构

### 可信业务服务

Web 静态服务、FastAPI、任务调度器、业务工具网关和模型网关使用经过构建的固定版本镜像。应用目录、模板、技能、依赖与配置只读，服务使用无特权身份。生产不挂载开发者的 `D:\项目\LLM_research`，不挂载 `.git`、SSH 密钥或开发者主目录，不开启源码热重载。

将 [settings.py](D:/项目/LLM_research/apps/api/app/settings.py:9) 中可变路径从 `PROJECT_ROOT` 分离，新增明确的 `STATE_ROOT`、`UPLOAD_ROOT`、`ARTIFACT_ROOT` 和 `SANDBOX_STATE_ROOT`。现有 `runtime`、上传目录、原件快照、生成公式缓存和维护账本都迁入数据卷。配置通过可信环境或只读 secret 提供。Python 字节码、浏览器缓存、字体缓存和日志不得要求写入应用目录。

应用身份没有发布权限，也没有创建任意宿主机容器的权限。独立沙箱管理服务只接受预定义任务模板及内部任务 ID，由它校验镜像、挂载和资源限制。用户和代理不能指定宿主路径、镜像、启动命令、UID、网络策略、SDK 配置或提权参数。

Docker 的只读根文件系统只保护根文件系统，另外挂载的数据卷仍可能可写，因此所有挂载都要逐项审查。Docker socket 能控制宿主机容器，禁止挂载给 API、普通 worker 和代理。[Docker 官方运行说明](https://docs.docker.com/reference/cli/docker/container/run/)

### 代理研究沙箱

Python SDK 和 app-server 在研究沙箱内运行，由镜像内的最小研究会话入口控制。可信调度器发送任务描述并接收事件，不把完整业务应用放进代理环境。可以继续使用同步 SDK，因为任务在后台执行；不要为了多用户而把长任务放回 HTTP 请求内。

研究沙箱中的资源范围如下：

- `/opt/research-runtime`：固定 SDK、Codex、Python、文档库与薄 MCP 客户端，只读。这里仅包含执行所需的程序，不包含完整业务项目。
- `/inputs`：当前任务获准使用的资料快照与附件，只读，路径重映射为沙箱路径。
- `/market`：当前任务获准使用的公共行情版本，只读。付费或租户专属数据需要分别授权。
- `/workspace`：当前对话的脚本、来源抓取文件、临时研究内容和 `outputs`，可写。
- `/codex-state`：仅属于该用户、该对话的 Codex 状态，可写。不能共享开发者 `.codex` 或其他用户的状态。
- `/tmp`：受容量限制的临时空间，任务结束后清理。

沙箱内看不到生产源码目录、生产数据库、其他用户根目录、宿主进程、宿主网络、设备和容器管理 socket。禁用提权和特权容器，不共享宿主 PID/IPC 命名空间，删除无关 capabilities。宿主可写卷仅挂载当前任务的子目录。

继续采用固定的 `workspace-write`、拒绝扩大权限的审批策略和可信配置覆盖。禁止从用户工作区自动加载可执行 hooks、插件或替代 MCP 配置；代理写入的脚本只能作为研究文件运行。恢复线程时重新应用当前服务器策略，不能从保存的线程继承更宽权限。

官方权限文档说明新版 permissions profiles 与旧 sandbox 配置不叠加。第一阶段沿用项目已使用的配置体系，锁定 SDK 与运行时版本；如切换 profiles，要整体迁移并验证，不同时保留两套配置。[官方权限文档](https://learn.chatgpt.com/docs/permissions)

首个技术验证必须测试锁定版本的 app-server、原生 shell、MCP、图像读取和 Playwright 在 gVisor 下的兼容性，以及内外两层沙箱组合。如果嵌套沙箱不可用，先验证该固定版本是否能在已经隔离的环境中采用外部沙箱配置；不自动退回宿主执行或放宽权限。技术验证未通过时，关闭对应功能，阻止上线。

### 公式与选股计算沙箱

新版 `python-screen-v1`、`python-indicator-v1` 和旧版生成公式统一经过一个 `ExecutionBackend`。可信 worker 只准备数据和验证结果；隔离计算进程运行源码。保留现有公式合同、有限性检查、前缀复算与版本证据。

计算沙箱使用无网络模板，不持有模型网关、业务工具或存储凭证。源码和有效输入用结构化请求传入，输出用有界 JSON 返回，不反序列化 pickle，不把生成模块导入 API 或可信 worker。旧公式保持自己的输入输出合同，先增加隔离适配器，再逐步统一实现。

建议初始上限为每个纯计算任务 1 GiB 内存、2 CPU、64 个进程、60 秒墙钟、64 MiB 输入和 20 MiB 输出，沿用现有量级。研究沙箱可先配置 4 GiB 内存、2 CPU、128 个进程和现有研究时限；这些是启动配置，需用实际大行情、浏览器和文档任务压测后调整。所有沙箱还要限制磁盘、临时目录、文件数和并发总量，不能只靠 Python 轮询内存。

## 四 用户权限模型

### 用户登录和角色

第一版采用受支持的 OIDC 登录，后端维护可撤销会话。页面和 API 使用同源 HTTPS；浏览器持有 `HttpOnly`、`Secure`、适当 `SameSite` 的会话 Cookie。修改操作增加 CSRF token，继续检查 Origin，但匿名 CLI/MCP 请求不再作为例外放行。提供 `/auth/login`、`/auth/callback`、`/auth/logout` 和 `/api/v1/me`。

平台管理员管理账户、模型策略、配额和公共数据导入；租户 owner 管理租户成员及显式共享；editor 可创建研究并修改自己或明确授予编辑权的资源；viewer 只读明确授权资源。平台管理员并不因此获得源码修改或发布接口。正常运营界面也不默认读取所有私人研究，运维访问采用单独审计入口。

第一版个人租户只有一个成员，普通用户可使用完整研究能力。未来开放团队时，资源默认仍是 private，只有显式设置共享后，团队成员才能按角色读取或编辑。

### 统一授权入口

新增冻结的 `ActorContext`，包含 `user_id`、`tenant_id`、角色、会话 ID 和权限版本，由服务端验证身份后创建。创建资源时由服务端填充归属，忽略或拒绝用户在正文、查询参数、URL、Header 和工具参数中提交的归属声明。

所有资源入口调用统一的 `require_resource(actor, resource_type, resource_id, action)`。service/store 必须显式接收上下文，未提供上下文时拒绝，不默认回到 `local` 或全局查询。跨用户引用也要检查目标资源，包括 project_id、附件 ID、原文 source_refs、已存方案、指标版本、运行 ID 和观察池。

用户查别人的资源统一返回 404；未登录返回 401；已登录但不具备某项角色能力返回 403。列表、搜索、统计、下载、流式事件、取消、重试、分支、重新生成、分享、PDF 生成和历史导出使用同一规则。UUID 只作为标识，不能作为访问凭证。

全局行情同步、文件系统扫描式导入、维护诊断和供应商连接测试只对平台管理身份开放。审核 [main.py](D:/项目/LLM_research/apps/api/app/main.py:994) 的资料导入接口和 [product_api.py](D:/项目/LLM_research/apps/api/app/product_api.py:135) 的维护接口。用户上传研报走私有上传流程，不能触发全局目录扫描或将文件自动变成公共资料。

### 任务身份传播

HTTP 请求授权成功后，在事务中写入任务的 tenant、请求用户、资源 ID、权限版本和数据版本。worker 领取任务后重新读取用户状态和权限，再构造执行上下文。取消、重试和成果回写都校验任务归属与当前 lease。

账号停用、成员移除、资源授权撤销和权限版本变化必须影响已排队及正在运行的任务：不再开始新执行，撤销网关凭证，取消受影响沙箱，拒绝迟到结果提交。登出只撤销网页会话，已经明确提交的后台任务可继续；用户可在任务页面单独停止。

## 五 数据库和文件隔离

### 需要补齐归属的资源

身份表新增 users、tenants、tenant_memberships、sessions。业务资源新增不可为空的 `tenant_id`、`owner_user_id` 和必要的可见性/共享关系。

需要覆盖的业务集合包括：对话与消息、回合、任务修订、Codex 线程和事件；研究项目、笔记、版本、断言和观察记录；筛选条件、策略、形态、已保存方案及版本；指标试算和版本；筛选、扫描、评估任务和结果；附件、研报原件、文档页、私有资讯、来源证据、PDF 和原格式成果；分享记录、工具调用、执行授权、审计与幂等请求。

子表可以通过已授权父资源继承权限，但数据库要约束父子 tenant 一致。含外部资源引用的记录要使用复合外键或等效约束，避免只通过一个全局 ID 连到其他租户。执行请求和任务的身份由服务器生成，不信任 JSON payload 中自带的 tenant 或 user。

所有用户提交的幂等键改为 `(tenant_id, user_id, operation, request_id)`，比较原始请求哈希。跨用户同名 `request_id` 不冲突，也不能重放别人的响应。上传、指标保存、助手启动、分支、分享和条件提交都纳入，不只修正一张表。

### PostgreSQL 权限与迁移

在私有业务表启用并强制 RLS，规则同时检查 tenant 与资源可见性/用户授权。只匹配 tenant 无法保证未来团队中的私人资源隔离。API 和普通 worker 的数据库角色不能是表 owner、superuser 或拥有 `BYPASSRLS`；迁移身份与运行身份分开。PostgreSQL 官方文档说明这些身份可以绕过普通 RLS。[PostgreSQL 行级安全说明](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)

每个事务由可信服务设置当前 actor 和 tenant，缺少上下文时不返回私人数据；连接池复用不能残留上次身份。系统调度账号只读取必要队列元数据，业务执行在对应用户上下文内进行。RLS 是数据库防误查的一层，不能代替业务授权，也不向代理提供数据库凭证或任意 SQL 接口。

[db.py](D:/项目/LLM_research/apps/api/app/db.py:17) 目前直接连接 SQLite。迁移必须处理 `?` 参数、`PRAGMA`、`BEGIN IMMEDIATE`、SQLite 的冲突语法、迁移触发器及大量 `rowid` 排序，不只是替换连接字符串。给消息、事件和版本增加稳定的显式顺序，保持分支、重新生成、快照和幂等行为。

现有本地数据默认迁入一个明确的管理员个人租户。`owner_id=local` 映射为真实用户；PDF 等表示业务父资源的 owner_id 保持其原含义。研报和资讯在没有明确公共归属证据时先归为该用户私有，公共化由管理流程显式完成。保留原业务 ID、线程映射、版本和哈希。

迁移期间停止写入，备份数据库和原件，导入 PostgreSQL，核对行数、关系、消息顺序、文件哈希及两用户隔离，然后切换。失败回滚使用迁移前快照；上线产生新数据后不能简单覆盖回旧库。回滚期间保持外部入口关闭，不能恢复成匿名工作台。

### 资料、缓存和对象存储

公共行情、公开目录与内置模板由数据维护服务发布为不可变版本，代理只读。用户上传的 PDF、Office、图片、CSV、笔记和分析结果默认私有，即使名称相同或内容哈希相同也不会变成其他用户可见。

先在第一版按 tenant 存储原件；不要保留全局 `sha256` 去重所带来的跨租户“已上传”响应。[documents.py](D:/项目/LLM_research/apps/api/app/documents.py:82) 的导入去重需要改为租户内内容关系，文档 ID 和可见性独立于文件哈希。内容相同也要有独立授权记录。

对象键由服务器生成，例如 `tenants/<tenant>/users/<user>/conversations/<conversation>/artifacts/<artifact>`。仅传入对象键前缀不足以授权，每次访问仍先查资源记录。下载使用已授权 API 或短期签名 URL；签名 URL 的持有者在有效期内可以访问，因此敏感文件优先 API 下载，并明确签名 URL 的撤销期限。

公开分享是显式发布能力，创建时同时校验对话归属、分享权限和每项来源的可发布范围，按所选回答冻结快照。租户可关闭公开分享；仅获准阅读的材料不能因为被引用而自动公开。撤销分享由所属用户执行，撤销后公开服务停止返回内容，已被接收者下载的副本无法撤回。

保留现有附件哈希校验、大小限制、路径遍历防护及 symlink/junction 拒绝。成果收集器只接受 outputs 内的普通文件，拒绝链接、设备、FIFO、路径穿越和超限文件；用安全的文件句柄校验并读取，避免检查后被替换的竞态。成果先归档到不可变对象，再给浏览器下载，不让 API 直接打开代理可持续修改的目录。

搜索索引、评估缓存、资料摘要和向量索引若以后加入，也必须带租户、资源权限版本和数据版本。私有内容不进入跨用户全局缓存。日志、错误、进度和统计同样属于隔离范围；前端不返回宿主绝对路径、长效密钥或其他用户资源数量。

### 授权后的研究快照

把 `_snapshot(path)` 改为 `_snapshot(path, access_scope)`。access_scope 来自可信 actor、任务和资料授权，而不是代理自由提交的条件。先计算可访问 document/news ID，再查询对应元数据、页面和正文；只将获准原件复制或挂载为任务输入。

资料权限范围与研究业务范围分开：用户说“不限股票、不限日期”只能扩大业务检索范围，不能扩大到其他用户的材料。快照记录 actor、tenant、权限版本、资料版本、哈希和本轮输入集合，SQLite 在沙箱内只读。

权限撤销后，不复用包含被撤销资料的旧快照、持久工作区或 Codex 历史来启动新回合。终止受影响任务并废止旧执行状态，需要续聊时从仍获准的内容创建新的安全上下文。已经合法交付给用户的文本不能通过撤销权限从其记忆或本地下载中收回，这不影响阻止后续访问。

## 六 业务工具网关和模型网关

### 将现有 MCP 改为受控调用

保留现有工具名称、参数合同和研究/选股工作流分工。将 business handler 放在可信服务端；沙箱中的 stdio MCP 进程只作为客户端，经网关调用业务能力，不加载业务数据库模块。

调度器签发不可伪造的短期任务 token。服务端保存 token 哈希及 `tenant_id`、`actor_id`、conversation、turn、job、lease generation、允许工具、数据范围、有效期和配额。网关从记录恢复上下文，不用工具参数或沙箱环境里的 user/tenant/conversation 作为认证来源。

每次工具调用检查任务仍有效、用户仍有效、租约仍有效、资源仍获准，以及该工作流是否允许此工具。调用时还要重新验证任何跨资源参数。旧任务 token 不能用于新回合、其他任务或其他用户；重复副作用调用用服务端幂等键去重。

文件类工具返回 artifact ID 或沙箱映射路径，不接受任意宿主绝对路径。PDF/图像核验和外部抓取在独立解析/浏览模板中运行，把内容通过安全的成果通道交还研究沙箱。接受 source_code 的工具只能提交隔离计算任务，不能在网关本身执行代码。

### 长期凭证移出代理环境

`_runtime_environment()` 改为显式环境白名单，停止复制宿主 `os.environ`，不传入 `LLMR_DB_PATH`、供应商 API key、数据根目录和业务应用 `PYTHONPATH`。Codex 使用模型网关地址和只允许本任务推理的短期 token。网关按已冻结的模型选择、任务、用量和配额转发到供应商，长效模型密钥留在网关。

模型网关只提供必要推理协议，不成为任意 HTTP 代理；任务 token 不能管理模型供应商账户、读取其他会话或访问业务管理接口。取消、停用和配额耗尽后撤销 token。沙箱内能读到自己 token 的生成代码也只得到这些受限能力。

行情查询、公共分享写入和对象存储同样留在各自可信服务。日志清除 Authorization、Cookie 和短期 token，限制工具返回和进度消息中的敏感字段。

## 七 网络和不可信文件处理

研究沙箱只连接指定的模型网关、工具网关和受控出站代理。网络层默认拒绝私网、回环、链路本地、云元数据、宿主网关及其他用户沙箱，不能直接访问生产数据库、存储管理接口或公网任意端口。所有 IPv4/IPv6、DNS、连接和重定向路径都要受限制，不仅检查用户输入的 URL。

现有 [public_sources.py](D:/项目/LLM_research/apps/api/app/public_sources.py:74) 有公开地址解析和连接校验，继续复用。代理能直接运行 Python 或 Playwright，因此还需要执行网络的出站控制，确保这些路径不能绕过受控 fetch。公网研究允许通过代理访问公开 HTTPS 来源；这也意味着代理可能把当前获准资料发到公网，涉及保密材料的任务应采用禁网模板和经过批准的来源抓取工具。

PDF、Office、图像、OCR 和网页解析采用无业务密钥的专用执行模板。禁用宏和外部链接自动执行，限制解包后体积、页数、像素、运行时间、子进程与磁盘使用。已有附件限额继续保留，并补上租户总体存储配额。

原格式成果默认附件下载，不在应用同源执行生成 HTML 或 JavaScript。网页原文预览隔离来源并设置 CSP；现有回答 Markdown、链接和图像 URL 也要验证，防止跨用户链接和脚本内容进入应用。

## 十 必须通过的安全验收

### 用户权限和数据隔离

1. A、B 分别创建个人租户。A 用 B 的真实 ID 请求对话、消息、文件、来源、指标、任务事件、运行结果、下载、导出、取消、重试、分支、分享和观察记录，全部失败且不改变 B 的状态。
2. 同一团队中 A、B 各建私人研究；未显式共享时互相不可见。viewer 不能上传、编辑、执行、分享或管理成员；editor 不能修改平台策略或其他人的私人资源。
3. URL、Header、正文、引用和工具参数伪造 tenant/user/project/attachment/version ID 无法改变授权上下文。匿名、过期会话、CSRF 请求和无 Origin 请求不能绕过认证。
4. 两个用户使用相同 request_id 不冲突、不互相重放。全局去重、搜索计数、缓存和错误响应不泄露另一个用户的私有资料存在情况。
5. A 上传仅有其可见的研报并开始研究；检查 B 的 SQLite 输入快照、原件挂载、资料搜索、代理历史和成果，均没有 A 的内容。权限撤销后的续聊不重新挂载旧内容。
6. 同一数据库连接连续服务 A、B，身份不会残留；缺少身份事务默认拒绝。后台任务不能通过旧 worker、旧 token 或伪造 payload 获得新授权。

### 源码保护和执行隔离

7. 在研究和计算环境分别尝试覆盖、追加、删除、重命名和 chmod 应用模块、前端发布文件、依赖、模板、配置、Git 和宿主项目路径，均不可写或不可见。API 和普通 worker 的运行身份也不能写入发布目录。
8. 尝试通过 `..`、绝对路径、symlink、hardlink、junction、文件替换竞态以及生成文件下载接口访问应用目录或另一用户文件，均被拒绝。验证挂载与命名空间配置，不能只检查任务前后源码哈希。
9. 恶意提示要求关闭 sandbox、请求提权、修改 SDK 配置、执行自建 hooks、安装替代插件或调用容器管理接口，不能扩大外层权限或网关能力。
10. 生成程序读取环境、宿主 `/proc`、本地配置、数据库、云元数据或供应商凭证，不得到长效密钥及其他用户数据。计算环境完全无网，研究的直连 socket/HTTP/Playwright 也不能访问受禁止网络。
11. 新指标、新选股和旧公式三个入口都只能调用隔离后端。沙箱服务不可用时任务明确失败，不能回退到业务进程的 exec 或本机 subprocess。
12. 无限循环、进程增长、内存增长、磁盘填满、过大输出、异常 ZIP、PDF 和图像触发实际资源限制；结束后无残留进程、容器和未撤销 token，不拖垮其他用户。

### 正常功能和生命周期

13. 正常研究仍可联网检索、读取授权原件、试算图表并交付 PDF、Word、Excel 和 PPT；只读发布目录不影响这些功能。
14. 同一对话串行，多对话并发时状态隔离；停止、超时、worker 崩溃和权限撤销后沙箱完整回收，迟到事件与成果不能写回已失效任务。
15. 分支、重新生成、历史模型选择、冻结日期、方案版本、公式合同和正式执行授权保持既有语义；修改 SDK 的兼容性测试不得改变安全策略。
16. 退出 A 并登入 B 后，浏览器草稿、附件意图、缓存、当前对话及流式连接没有 A 的私人内容。私有分享创建、撤销和公开快照不调用接收者无权访问的本地 API。

保留现有 `tests/integration/test_request_security.py`、`test_codex_web_route.py`、`test_codex_mcp_protocol.py`、`test_research_attachments.py` 和动态指标/执行协议测试，按新的身份上下文更新。另增多用户授权、资料快照、RLS、网关 token 和真实沙箱测试。普通 mock 无法证明源码权限和系统隔离，最后一组必须在与生产相同的 Linux 运行时上执行。

## 十一 上线阻断条件

以下任何一项存在都不开放外部用户：没有统一身份和资源授权；资料快照包含未经授权材料；任一生成代码或文档解析路径回落到持有业务密钥的进程；执行身份能看到生产源码可写挂载；长效凭证进入代理；沙箱失败时自动放宽权限；权限撤销和任务取消不能终止后续业务写入。
