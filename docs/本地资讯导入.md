# 本地资讯导入

在资讯库右上角点击“导入”，填写 HTTP / HTTPS 网址。后端启动隔离的无头 Edge（没有 Edge 时使用 Chromium），读取渲染后的正文，调用已配置的模型整理标题、正文、来源、发布时间和证券代码，保存到本地资讯库。失败时显示原因，不保存无效模型输出。同一请求重试不会重复抓取或保存。

浏览页默认展示资讯列表和正文，A+ / A- 调整阅读字号。描述需求中的日期区间按北京时间自然日先筛选本地资讯，再由模型判断匹配；匹配记录中的引用必须能够在原文核对。无明确发布时间的网页使用抓取时间作为首次可用时间，避免回填到过去。

文本和 JSON 的批量导入保留为兼容 API，不占用浏览页面。JSON 接受一个对象或最多100个对象组成的数组。例如：


```json
[
  {
    "title": "公司新增订单公告",
    "body": "这里填写实际资讯原文。",
    "source": "公司公告",
    "stock_codes": ["600000.SH"],
    "published_at": "2026-09-14T09:00:00+08:00",
    "available_at": "2026-09-14T09:05:00+08:00",
    "event_key": "示例公司-同一订单事件"
  }
]
```

- title、body、source为必填文本。正文按录入内容保存。
- stock_codes使用完整证券代码，无法确认时填空数组；不从公司名称猜测代码。
- published_at为发布时间，available_at为首次可获得原文的时间。时间须带时区；不明确时填null。首次可用时间不能早于发布时间。
- event_key为选填。同一事件的多篇转述可填写相同标记，供后续事件分析使用。

重复导入相同内容及元数据不会增加记录。修改正文、来源或归属会创建新版本；旧正文仍可读取。日期筛选采用北京时间的自然日边界，不能使用截止日后的资讯。新版本可用日期未知时，不会自动退回旧正文冒充当前已确认资料。

API入口：`POST /api/v1/news/import-url`接收`{request_id,url}`；`POST /api/v1/news/import`接收`{request_id,items}`；`POST /api/v1/news/import-text`接收text/plain正文及标题/来源等查询参数；`GET /api/v1/news`支持query、stock_code、start_date、end_date、offset、limit；`GET /api/v1/news/{id}`读取原文；`POST /api/v1/news/{id}/revisions`接收`{request_id,item}`。

request_id用于防止网络重发导致重复创建；同一ID绑定不同请求会被拒绝。批量字段校验失败时整批不写入。编辑过期版本会返回冲突，应先刷新。

这里只处理本地输入，不连接外部实时资讯供应商。L16已将资讯条件接入对话筛选：模型选择资料阅读步骤，再核对事件阶段、主体、期间、数值单位和独立事件数量。多篇转述不等于多个独立事件；计划不等于已完成。真实模型语义质量仍待L22验收，当前状态以实施进度表为准。
