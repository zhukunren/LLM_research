# 页面切换稳定性修复

2026-10-04，响应“切换页面时页面会抖动”。验证从 10 月 3 日晚开始，记录统一存放在 `artifacts/page-switch-20261003/`。

## 原因与处理

- 长短页面和加载状态交替时，文档滚动条出现、消失，顶部与内容区横向移动；在显示普通滚动条的 Edge 中复现了 10px 偏移。根元素固定滚动条占位，页面可用宽度保持稳定。
- 切页沿用旧页面的文档滚动位置，异步内容的高度变化又让浏览器连续调整位置。主页面实际切换后，在绘制前立即回到顶部；重复点击当前资料库保持阅读位置。
- 主页面容器按页面键值重新挂载，首次下载页面代码时退回一行加载文本。保留共用容器，用 React transition 等待页面代码，期间保留原页面并显示顶部切页状态。首次启动和资料内容加载有稳定的占位高度。
- 窄屏页面原本强制最小宽度 320px，与滚动条占位叠加后可能产生横向滚动条，使固定底部导航上下移动。根布局允许使用实际可用宽度，页面最小高度同时计入移动端底部导航。

页面业务状态和草稿仍由原组件维护；切到新页面后，原页面按原有方式卸载，不会为了消除加载画面把全部页面长期挂载。

## 验证方式

使用隔离合成数据库，在 Edge 中保留普通滚动条，将 GET 数据响应延迟 220ms、页面代码延迟 450ms，以逐帧记录定位变化。覆盖七个主页面的首次切换、从已滚动页面切出，以及 1440 / 820 / 390 / 320px 四种宽度。

四种宽度下 40 次切页断言全部通过：根布局和顶部尺寸变化为 0，顶部操作区横向位移为 0，新页面显示后的标题纵向位移为 0，没有标题空白帧，文档滚动位置均为 0。另有 12 项检查通过，覆盖各宽度下的当前页重复点击、PDF 专注阅读与服务抽屉的滚动锁定、页面代码尚未加载时快速连续导航。手机底部导航的 10px 位移已消除；桌面侧栏测量最大偏差 0.2px，在 1px 验收容差内。

原有九组完整功能流程通过：项目草稿与保存、研究对话与笔记、观察记录、资讯阅读与搜索、指标与条件创建、条件版本与组合、形态草稿与保存、PDF 阅读、服务检查和诊断下载。本地 5173 页面已经加载新的导航与样式，8000 API 健康状态为 `ok`。

机器可读结果见 [切页测量](../artifacts/page-switch-20261003/validation.json)、[修复前复现](../artifacts/page-switch-20261003/baseline.json) 与 [完整交互回归](../artifacts/page-switch-20261003/functional.json)。`viewport_width_shift` 记录实际滚动条对 `clientWidth` 的影响；固定占位后的布局稳定性以根布局、顶部和操作区的边界尺寸判断，不要求这个浏览器属性保持不变。

前端原有 18 个测试文件、60 项测试及 TypeScript/Vite 生产构建通过。交互回归使用合成资料和测试答复，验证界面与业务状态，不调用外部模型。本次没有修改后端业务逻辑。
