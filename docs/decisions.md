# 实施决策

## 2026-09-29 投研 Web 服务与 Codex 内核：目标架构，尚未实施

用户明确服务对象没有 Codex，需要通过 Web 提供服务；目标是充分利用 Codex，避免自建 Agent 和渐进堆叠造成持续增加的投入。推荐自有投研 Web 界面，以服务端 Codex App Server 为唯一研究 Agent 内核，SDK 负责接入，Skills 和 MCP 提供投研方法与业务工具。

新架构按目标形态完整构建并统一验收切换，旧自建 planner、工具循环和重复模型执行路径随后退役；历史资产通过转换或只读视图保留，不以长期双轨执行维持兼容。现有数据、有效计算算法与显示组件按能力复用。Web 服务需要核对用户归属、执行隔离、配额和任务恢复，不能将当前本地版本直接视为已具备这些能力。

本方向取代此前继续扩展自建 Agent 的设计目标，详见 [投研 Web 助手目标架构](投研版Codex式助手演进建议.md)。SDK 依赖、适配代码和数据库迁移已开始实施；新入口和业务动作尚未统一切换，旧进度文档仍是历史实现与验证记录。

### 2026-09-29 Codex 第一条后端垂直链路：已实现，运行时就绪后自动切换

已加入 `018_codex_runtime.sql`、Codex SDK 适配、投研 Skills、stdio MCP 工具桥、Codex thread/turn 关联、回合事件持久化和 `/process` Codex Web API。真实本地回合已验证 SDK/App Server 启动、MCP 工具列表和事件落库；离线回归通过。

`/{conversation_id}/turns/{turn_id}/process` 只走 Codex。Codex MCP 动作现在可以保存结构化 `ScreeningTaskRevision`、记录服务端校验的执行授权，随后复用现有 `screening_service` 创建运行；未安装锁定 Codex CLI runtime 时返回明确的 runtime unavailable，不再启动旧 planner。完整真实模型任务仍需继续扩大验收，不能把单次 smoke 当成生产质量证明。

本轮新增 MCP stdio 协议集成测试，并用真实 App Server 直调 `get_research_state` 验证环境传递和工具返回。离线模型形状修复覆盖 `type/domain/condition_type`、非规范逻辑树、缺失范围和未完成 Python 程序；真实模型仍可能反复修正复杂任务合同，后续需用代表性中文任务集统计并降低这类修正次数。

## 2026-09-28 对话式股票筛选：规划目标，尚未实施

本轮采用持久对话明确口径、LLM自主选择工具与算法、平台校验输入输出并保存可追溯结果的方向。产品只做股票筛选，不引入回测、自动调参、绩效搜索或根据命中数量改条件。保留六个菜单，“策略库”沿用组合选股中的已保存组合。

新算法目标为隔离环境中的标准Python，旧DSL及受限源码用于既有资产兼容；新路径未验收前不改变旧条件行为。开发计划按GPT-6 Luna拆为L00—L23，应用模型配置独立保留。完整决策、依赖和验收见 [主计划](对话式股票筛选实施计划_Luna6.md)，实际实现状态只看 [本轮进度](对话式筛选实施进度.md)。

## 2026-09-27 分类资料库与统一组合

用户明确四个资料库同时承担内容浏览和自然语言条件创建。一级菜单采用观察池、资讯库、技术指标库、形态库、研报库、组合选股。各库内部提供浏览、描述需求和已保存条件；研报另有证据评估。

保留统一条件与组合引擎，按库隔离草稿，研报条件可带阅读页来源，形态增加文字生成可检查目标模板。统一组合引用固定版本，继承此前三值逻辑、股票池快照和逐股依据。详细实现与验收见 [资料库与条件工作流](library-navigation.md)。下列“自然语言选股工作台”导航决定为上一轮记录，以本段为当前产品入口设计。

## 2026-09-27 自然语言选股工作台

- 主流程调整为“描述条件 → 核对口径 → 保存独立条件 → 组合选股 → 查看依据”。普通用户不必预选技术库/资讯库，执行代码不作为主要交互。
- 条件必须完整解析；模型只产生白名单结构。未支持要求阻止整份草稿被当作完整请求确认。保留原话、补充记录、模型、原表达式及人工修改。
- 提交时固定条件版本、股票池名单和研报评估。每只股票的判断都保存。新任务带执行协议，SQLite 拒绝旧版 worker 领取，已完成快照不能更新，重试创建新记录。
- 详细设计和验收见 [自然语言选股工作台](condition-workbench.md)。

## 2026-09-27 系统完善补充

- 当前行情、研报按用户要求视为示例；软件功能、受控流程测试先完善，生产数据完整性与正式筛选口径后续单独验收。
- 技术条件覆写使用 `parameter_overrides`，只开放指标周期、已有数值阈值及均线周期/方向；复用已发布条件时保留原资产，覆写随策略版本保存。证据类条件不允许静默覆写，避免绕过评估缓存版本。
- 策略前端直接编辑递归逻辑树，不再把树扁平化为分组清单，避免丢失组级 NOT、重复引用与参数。
- OHLC 新版本使用 `normalized-candles-v1`，权重为路径 40%、实体 20%、影线 20%、方向 15%、跳空 5%。这是可解释的启发式距离，不是经过市场收益标定的概率。历史 `normalized-path-v1` 保持原行为。
- SQLite 原子领取任务，90 秒租约、15 秒续约；失效任务重新排队，从头执行并复用已验证研报缓存，最多自动尝试三次。取消与最终写入共用事务锁，旧 worker 不能覆盖新拥有者或取消状态。
- 手动重试建立独立运行，通过 `retry_of` 唯一索引保证同一重试请求幂等。旧结果、策略版本和截止日保留。
- API/worker 同时启动时，迁移在同一写事务内串行执行；版本保存也串行分配版本号。Windows 服务脚本用进程命令及创建时间识别归属，重复启动复用健康服务。
- 数据画像缓存随源文件属性变化自动刷新。备份保留上传文件子目录，恢复验证所携带文件哈希并更新研报路径。

## 已采用

| 决策 | 理由 |
|---|---|
| React + TypeScript + Vite，FastAPI + Pydantic | 与首期计划一致；前端构建产物可由 API 服务托管，也可在开发时独立运行。 |
| SQLite 标准库 + 有序 SQL 迁移 | 单用户本地场景无需额外数据库服务；避免为元数据增加不必要进程。资产版本采用 `(id, version)` 复合主键。 |
| DuckDB 只读 Parquet，PyArrow 读取元数据 | 用列式查询检查 1,693 万行情行；不把行情逐行写进 SQLite。 |
| 后台 worker 轮询 SQLite 持久任务表 | 本机全市场筛选与 HTTP 请求解耦；启动时会把遗留 running 任务重新排队。 |
| 规则 DSL 只接受白名单节点 | LLM 和用户文本都不能提供可执行 Python 或 SQL；状态采用 true / false / unknown。 |
| 资讯供应商暂不接入；正式运行阻断 | 当前没有核验账户权限与资讯能力，不能用演示或假数据替代。 |
| 文本模型配置读取现有 `config.ini` | 用户明确要求模型设置和凭证写入 `config.ini`；只读取指定 provider/model/secret 字段，密钥不返回前端或日志，文件由 Git 忽略。Responses 请求设置 `store:false`。 |
| 使用系统 Python + `runtime/python-deps`，不创建虚拟环境 | 用户明确要求不使用虚拟环境；锁定依赖放在运行目录并通过启动脚本设置 `PYTHONPATH`，避免替换其他项目依赖。 |
| 截图首版提取彩色像素路径并人工校正 | 适用于清晰主图候选走势；不宣称恢复 OHLC、价格轴、证券或日期。复杂图表必须校正；质量评测集尚未完成。 |
| 真实结果默认探索模式，正式筛选检查口径 | 复权、量额、证券主数据和交易日历尚未核验。 |
