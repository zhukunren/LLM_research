# 可选的备份保留策略

`python scripts/backup.py <新备份目录>` 仍然默认保留所有旧备份，不执行轮转。

需要轮转时明确传入 `--retain-count N`，其中 N 必须至少为 1。N 表示保留最新的 N 份非固定受管备份，包含本次新备份；带 `.keep` 的固定备份额外保留，不占旧备份配额。数量应由恢复目标、备份频率、容量及合规要求决定，没有通用的“三份”默认值。

先预览轮转：

```text
python scripts/backup.py <同一备份父目录下的新目录> --retain-count N --retention-dry-run
```

**`--retention-dry-run` 不是整个备份操作的 dry-run。它仍会创建并完整校验新备份，只打印哪些旧目录将被轮转，不删除旧备份。** 核对结果后，下一次备份可使用新的目标目录并去掉该选项。目标目录不得已存在。

## 哪些旧备份会被考虑

- 只在本次新备份的父目录中查找直接子目录；不递归寻找备份。
- 只识别本版本创建、带受管元数据、同一数据集的完整备份。数据集标识由存储位置映射、数据源位置和是否复制源文件生成，不以文件内容或日期生成。
- 旧版无受管元数据、其他数据集、临时目录、损坏或不完整目录、含未知文件的目录全部保留。不会自动把历史目录“收编”为受管备份。
- 每份候选需通过完整文件清单、大小、SHA-256、数据库完整性和路径检查。链接、junction/reparse点、越界路径均不接受。
- 重要版本可在备份根目录内创建空文件 `.keep` 固定保留；轮转前会重新检查。请在运行备份前固定版本，不要在轮转过程中编辑备份目录。

## 失败和并发

同一父目录下本工具的备份与轮转使用排他 `.llmr-backup.lock`。检测到已有锁即失败，不会自动猜测或清除旧锁。遇到异常退出遗留锁，应先确认没有备份进程、检查现场，再由管理员处理。

只有新备份成功发布且发布后完整验证通过，才会开始轮转。新备份无论时钟是否回退都不会被本次轮转删除。快照、发布或发布后验证失败，不轮转旧备份。

删除前会重检候选身份、固定标记和完整性，先原子移动到同父目录的 `.llmr-retiring-*` 隔离目录再复核。文件系统删除失败时停止后续删除；新备份仍在，隔离目录保留供检查，可能已部分删除，不应当作可恢复备份。不会自动继续清理隔离现场。这个锁防护本工具的协作并发，不是对拥有目录写权限的恶意进程的安全隔离边界。

建议备份父目录仅允许备份管理员写入。不要在备份/轮转时手工重命名、替换目录或修改文件。

本轮只提供代码和合成临时目录测试，不执行用户现有历史备份删除。未加入自动任务、启动清理或 VACUUM。
