# 产品打磨记录 · 2026-09-29

本轮聚焦对话选股的完整使用过程：用户描述需求，核对系统理解，主动发起筛选，阅读结果，再把有效的条件保存下来。目标用户沿用项目定位：没有技术背景、需要结合行情和公开资料研究股票的本地用户。资料库导航和现有阅读样式沿用当前工作区设计。

## 产品判断与已交付改进

| 体验问题 | 本轮改进 | 用户可以验证的行为 |
| --- | --- | --- |
| 进入对话后，不清楚需求整理与执行之间的关系 | 增加“描述需求 → 核对条件 → 查看结果”状态；条件旁设置明确的执行与保存按钮 | 未确定条件、范围或截止日时引导补充；输入框有未发送内容时不能直接执行旧条件 |
| 条件列表把复杂逻辑展示成平铺列表，容易把“或”理解为“且” | 根据真实任务结构呈现“同时满足”“满足任一”“排除以下情况”，保留嵌套与引用参数调整 | 相同条件不同参数、嵌套排除均可在执行前核对 |
| 保存功能藏在对话和 API 中，无法便捷找回 | 增加命名保存、已保存任务列表、搜索、详情和在新对话中复用 | 保存与复用均不会自动创建筛选运行；复用保留原截止日，用户可继续修改 |
| 切换资料库、刷新或切换对话会丢失未发出的输入 | 在当前浏览器会话中按研究范围与对话分别保存草稿 | 返回原对话能继续输入；其他对话的草稿互不覆盖 |
| 只显示“未知”或空列表，用户无法决定下一步 | 改为“数据不足”，补充零命中、处理失败、取消、搜索无结果的恢复指引 | 可清除结果筛选、重新加载失败的请求、返回输入框调整要求 |
| 查看历史结果时，追问可能指向当前运行；详情显示内部条件编号 | 追问附带实际所查看的运行引用，解释名称读取该运行的条件快照；切换运行重置分页 | 旧运行的依据不会被当前任务名称替换；第二页切到另一运行后回到第一页 |
| 无法直观看到行情覆盖到哪一天 | 筛选页标题处和桌面侧栏显示接口返回的行情截止日 | 日期来自真实服务状态；侧栏日期可打开系统设置 |

## 接口修复

已保存任务复用后，原接口仅写入任务修订，没有结束对应用户回合。这会让前端认为上一条消息仍在处理，阻止继续输入。现在任务修订和回合回复在同一数据库事务内提交；复用明确不授予执行权限，不创建筛选运行。重复请求不会重复发布回复；遇到正在运行的模型回合会拒绝覆盖，发布失败时修订整体回退。

前端保存固定任务修订，重试保留相同资产标识。复用过程中若后续请求失败，可继续同一次复用。任务列表最多展示最近 200 个保存资产；对话列表沿用最近 50 条查询。
