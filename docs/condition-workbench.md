# 自然语言选股工作台

当前产品入口已按用户补充需求调整为四类资料库，浏览内容和自然语言创建同处一库，跨库组合独立执行；见 [资料库与条件工作流](library-navigation.md)。本文继续说明共同的条件执行契约与此前验收记录。

以没有技术背景的股民为使用者，主流程是：描述想法 → 核对每条判断口径 → 保存独立条件 → 自由组合 → 选择股票池和截止日 → 查看逐股依据。行情、研报、形态属于条件依赖或辅助资料，用户不必先理解底层分类才能开始。

## 使用流程

1. 输入“收盘价高于20日均线，且近5个交易日涨幅大于3%”，系统生成两个独立条件，保留原句和全部满足的关系。
2. 查看中文计算口径，必要时修改名称、周期、阈值，先对一只熟悉的股票试算。实际值、要求值和符合状态分别显示。
3. 确认后保存到“我的条件”。未解决要求、缺少数据的限制、失败的解析不能被当作完整请求保存。
4. 在“组合选股”选择条件版本，使用全部满足、任一满足、排除、嵌套分组。同一条件可以多次引用，并采用不同参数。
5. 选择全部 A 股或自建股票池，指定截止日运行。股票池可直接添加代码、备注，也能加入筛选结果；重复添加保留原有笔记。
6. 在“筛选记录”分类查看符合、不符合、数据不足，按股票代码搜索、分页、展开依据、导出优先结果。更新条件或增删股票池不会改变历史结果。

## 执行契约

草稿保留完整输入、最初输入、上一份草稿 ID、原文片段、解析方式、模型、编译器版本、假设、未解决问题、原子条件和组合树。确定性本地解析只接受完整匹配，绝不把一句话的一部分或默认示例当作整句。未匹配的自由描述交给已配置文本模型。

模型输出经过严格结构、白名单、原文引用和组合引用完整性检查。服务端独立检查市值、估值、ST、资金流等未接入能力。模型解析不能保证任意自然语言的语义准确，用户仍需核对最终中文口径；失败明确保留失败状态，不伪造规则。

确认保存是一次 SQLite 事务，全部原子条件及固定引用同时落库。重复提交相同内容返回同一结果；不同内容不会悄悄重复创建。生成参数被修改时，原表达式和确认修改同时保留。条件更新追加版本，`base_version` 防止覆盖并发编辑。

运行提交时固定组合版本、条件版本、股票池名单、截止日、行情文件指纹，以及当时已完成的研报评估 ID。重试创建新运行，保留原快照。执行前和结束时检查行情是否变化。股票池查询在 DuckDB 中直接限定所选代码。

每只证券的判断写入 `screening_decisions`：实际值、阈值、窗口、行情日期、来源、版本、参数和完整组合逻辑。逻辑路径区分重复引用。同一截止日没有行情时，不使用过期价格生成当日信号。“排除数据不足”仍是数据不足，不会变成符合。

结果、逐股判断和任务完成状态在持有有效租约的同一事务里提交。新任务要求 `condition-decisions-v1` 协议，SQLite 拒绝旧后台领取；完成的结果快照禁止更新。取消、租约失效、进程崩溃和重试均保留独立状态。

## 当前能力与数据边界

| 能力 | 口径 |
| --- | --- |
| 内置指标比较 | SMA、EMA、RSI、MACD、KDJ、ATR、布林上轨，限定字段与周期 |
| 自定义时序指标 | 模型可生成新公式和辅助函数源码，不依赖预设指标目录；源码模块按内容哈希保存和直接加载。模型只拿到截止日之前最多500根只读 OHLCV 数组，须返回等长的符合/不符合/未知时序及数值解释项。源码语法、开放数组函数、循环与输出范围经过校验；代码不具有文件、网络或进程接口。 |
| 均线当日上穿/下穿 | 同时核对前一交易日和当日，仅处于上方不算上穿 |
| 区间涨幅 | 最新收盘价 / N 个有记录交易日前收盘价 − 1，需要 N+1 根日线；阈值 3 表示 3% |
| 日成交量倍数 | 当日成交量 / 此前 N 日均量，不含当日，不等同于盘中量比 |
| 价格区间 | 通过价格比较原子条件组合上下限 |
| 研报证据 | 显式基于研报的研究问题，先完成对应截止日评估，保留页码、原文与覆盖情况 |
| 走势形态 | 已保存形态版本可继续加入组合 |

现有行情和研报作为流程验证数据，完整数据后续可补充。本地行情截至 2026-09-14；复权与量额口径尚未确认，当前为探索筛选。财务、估值、市值、行业归属、ST、资金流未接入；Tushare 快讯按受控同步结果读取，不代表完整实时资讯覆盖。连续满足、区间内曾经发生等时间逻辑暂不支持。研报股票归属和首次可用日期仍需核验，这些事实不能由模型猜测。

## 运行与升级

沿用系统 Python 3.12 和 `runtime/python-deps`，新增固定版本 psutil 核对进程目录。启动/停止脚本只处理当前 checkout 的 API、worker、Vite，即使登记文件丢失也能识别残留服务；同时核对命令与目录，不按进程名批量结束其他项目。

新增迁移 007、008，保留旧条件、组合与运行。旧运行没有全量依据时，界面明确只展示已有优先结果与未知样本。无需重建数据目录或修改配置凭证。
