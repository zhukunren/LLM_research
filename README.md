# LLM 投研工作平台

研究公司、阅读资料、按条件找股票，并把证据和判断保存下来持续跟踪。

## 打开工作台

已完成首次安装后，双击项目根目录 **`start.cmd`**。浏览器会自动打开工作台，关闭启动窗口不会停止后台任务。日常使用无需打开终端或运行安装命令。

首次安装和连接配置由维护者完成，参见[维护与开发](docs/维护与开发.md)。如果界面尚未构建，启动器会提示维护者先准备用户版。

## 做第一件事

左侧顶部使用 **研究 / 选股** 切换工作区。研究侧提供新研究、研究项目、研究助手和最近研究；选股侧突出 **新选股、我的方案、最近选股**。我的条件和高级组合在 **高级工具** 中；全部筛选运行记录在最近选股末尾，选股对话与运行记录分别保留原地址和历史。两侧分别保留所在位置、未发送草稿和历史记录。资料库、观察池及数据与服务在两侧共用，切换工作区不会启动研究或筛选。

打开后直接进入研究对话，输入公司、行业或问题即可开始。界面保留东吴证券原始标识，采用浅灰侧栏、白色阅读区，并参照东吴证券官网的深蓝与亮蓝统一主要操作、选中状态和焦点提示。布局保持简洁；配色依据与正式 VI 核对边界见[品牌来源](apps/web/public/brand/SOURCE.md)。

1. **新研究**：输入问题后发送，按问题中的公司、行业或时间要求展开，不需要先设置研究范围。输入框下方直接显示 **示例问题**，点击只会填入草稿，确认后再发送。已有对话采用大幅阅读区与底部输入框；项目归属和成果文件在页头查看。
2. **开始选股**：点击左侧一级入口，选择基础方案或直接描述要求。基础方案展示实际规则与当前参数，展开 **调整参数** 可修改；先查看方案，核对股票范围、截止日与数据状态，再点击 **确认并开始筛选**。选择方案不会自动执行，也不要求先建立项目。
3. **资料与工具 → 研报库**：选择已有材料或上传 PDF，从原文发起研究。

研究对话用简短状态显示正在搜索网页、阅读资料或生成答复，并提供用时与停止操作。研究、选股和资料处理的进展也可在顶部 **运行任务** 查看。需要补充要求或处理失败时，打开原工作按提示继续；**最近任务**可找回已完成或需重试的任务。

对话中的模型菜单可以选择模型和推理档位。当前账户无法使用的模型显示为灰色，并说明原因；Free 账户下 Astra 和 Sol 不可选。每次发送保存当轮的模型与档位，之后切换不会改写历史研究。

## 第一次选股

- 输入框下提供三个基础方案：**收盘价高于20日均线**、**近5日涨幅大于3%**、**5日均线上穿20日均线**。点击先展开预览，可调整参数，公式与说明按需展开；生成方案后再核对条件、范围、截止日与待澄清问题，确认后才执行。基础方案使用固定日线算法，不依赖模型解释；“高于均线”不等于“突破均线”。
- 模型与条件核验深度集中在 **选股设置**，沿用已选配置或服务默认值。模型不可用或读取失败仍在输入区提示，不会自动替换模型。保存、命名与项目归属在确认区的次级操作中。
- 自定义要求仍可用自然语言描述；不支持或资料不足的条件不会被静默删除。数据提示只说明来源可用性，逐证券覆盖与最终判断以执行结果为准。
- 正常数据状态合为一行，来源已接入不保证全部条件可执行；异常自动展开原因与处理入口。结果默认查看 **符合** 项，突出符合数、已判断覆盖与数据不足数，处理失败和未处理另行说明。展开股票可查看实际条件与依据，也可切换全部判断。**复制与导出** 菜单分别提供本页代码、当前搜索范围全部符合项和当前状态/搜索范围全部页导出。
- 无匹配、数据不足和运行失败分别提示；系统不会自动放宽规则凑出结果。得到结果后再决定保存方案或加入观察。

## 获得结果后

- **保存为研究笔记**：保留答复和出处。独立研究归入研究收件箱，项目研究归入当前项目。PDF 在后台生成，正文保存后可以继续工作；排版失败可以单独重试。
- **加入观察**：按公司名称或六位代码选择公司，检查系统带入的关注理由。验证计划和失效条件可以之后再补充。
- **转为选股草稿**：带入研究摘录和原出处，可继续修改。在条件选股中确认方案后，再决定是否执行。

项目和观察池以列表与正文为主，减少重复统计卡。研究答复连续展示，代码仍可按需展开。独立条件和高级组合用于长期复用要求，可在需要时展开。资料页默认以搜索和阅读为主，点击 **选股与条件工具** 展开进阶能力；形态页的匹配参数集中在 **匹配设置** 中。

点击 **成果与文件** 从右侧查看研究文件；点击答复中的研报或资讯引用，在右侧核对原文。研报会定位到引用页，也可在新窗口打开。关闭面板后继续原对话。

输入框左侧的 **＋** 可以上传文件或调用研究助手。附件保存在当前对话里，可上传 PDF、Word、Excel、PPT、CSV、文本和常见图片；每份最多 25 MB，每次提问最多 8 份。选好文件后输入问题并发送，也可以只发送附件让助手分析。已发送的附件可从消息中重新下载，未发送的附件可以移除或重试上传。

模型与推理强度在输入框右侧、发送箭头旁选择。需要表格或文档时，在问题中直接说明文件格式；助手可生成 Excel、Word、PPT 等原格式文件，答复中的文件链接及页头 **成果与文件** 都可以下载。原格式文件与品牌 PDF 报告同时保留。

股票名称与代码在对话和各类面板中以蓝色标出。点击可打开日线行情，悬停或键盘聚焦可选择 **加入观察池**；手机打开行情后也可加入。匹配使用证券目录和已确认的常用简称，不猜测重名公司；行情显示实际数据截止日。快速加入为手动关注，不生成研究或筛选任务，已有观察不会重复创建。

## 下次继续

点击左侧 **最近对话** 中的记录继续。具体对话、项目和观察记录有独立地址，可以保存书签；刷新和浏览器返回可回到原工作。未发送的草稿会保留，旧首页书签会自动进入新研究界面。

研究侧以 **新研究** 为首个入口；切换到选股侧后，以 **新选股** 为首个入口。**已保存方案** 可以按原截止日或最新行情复用，核对后再执行。资料库放在 **资料与工具** 中，数据状态在 **数据与服务** 查看。手机点击左上角菜单打开导航，顶部同样可切换研究与选股。

**研究助手** 是一级菜单，所有助手均已配置好，无需创建。点击以下子入口即可启动实时网页研究，结果会保存在研究对话中：

- **今日热点**：按重要性精选今日最重要的 10 条财经、市场与产业资讯，附事件时间和原始来源；可靠资讯不足时按实际数量交付。
- **政策追踪**：检索近 24 小时的重要政策原文，说明实施阶段和行业影响；没有实质更新时可补充近 7 天进展并标明日期。
- **产业动态**：梳理近 7 天的供需、订单、价格和产能变化，精选最多 8 项有据可查的动态。

**通用投研、财报分析、研报解读、产业链研究、风险复核** 仍作为同一菜单下的子入口，选择后输入自己的问题即可。每次发送会保存所用方法的版本，后续修改不会改变历史研究。

按 **Ctrl K**（Mac 使用 **⌘ K**）打开快速导航，可直接找回最近对话、项目或页面，也支持用空格组合关键词。研究页面点击示例问题只填入草稿，确认后再发送；**Enter** 发送，**Shift + Enter** 换行。

## 数据与服务

页面显示实际行情日期和质量状态。行情可查询、探索筛选可执行、正式选股就绪是不同状态，请按当前任务提示核对所需数据。

连接异常时重新双击 `start.cmd`；仍有问题，在 **数据与服务** 中重新检查并保存诊断信息交给维护者。

## 更新本地版本

维护者拉取最新代码后，在 `apps/web` 运行 `npm run build`，然后重新启动服务；只拉取源码不会更新已有的 `dist` 界面。模型选择、助手启动和对话附件分别使用 `031_research_models.sql`、`032_research_assistant_launches.sql`、`033_research_attachments.sql` 迁移，由应用初始化执行；更新前请备份数据库。文件读写依赖包含 `openpyxl`、`python-docx` 和 `python-pptx`，按 `requirements.lock` 安装。

## 模型与助手配置（维护者）

[配置示例](config.example.ini) 中的 `[research_models]` 由服务端控制账户和模型范围：

- `account_tier = free`：可用值为 `free`、`paid`、`enterprise`；环境变量 `LLMR_RESEARCH_ACCOUNT_TIER` 优先。此设置不会授予供应商账户原本没有的权限。
- `allowed_models =`：可选的逗号分隔模型白名单；留空表示不额外限制受支持的模型目录。环境变量为 `LLMR_RESEARCH_ALLOWED_MODELS`。白名单不能绕过 Free 账户限制。
- `reasoning_efforts_json = {}`：维护者核验过的模型档位映射，例如 `{"gpt-6-luna":["low","medium","high"]}`；环境变量为 `LLMR_RESEARCH_MODEL_EFFORTS_JSON`。未覆盖的模型使用内置档位。

模型目录结合以上策略与供应商 `/v1/models` 返回值决定可用性。未确认支持的备选模型保持禁用；发现服务暂不可达时，仅保留已显式配置且符合账户策略的默认模型，认证失败则全部禁用。`[app].reasoning_effort` 是新会话的默认档位；执行时使用当轮保存的选择，普通／深入研究的时限预算不会再把它强制映射为 `high`／`max`。

三个即时助手要求 `[research].web_search = live`（或 `LLMR_RESEARCH_WEB_SEARCH=live`），并需要模型服务实际支持联网检索；原生搜索还需在对应 `[model_providers.<名称>]` 中按实际能力启用 `supports_standalone_web_search`。变更供应商后应验证真实搜索和打开来源页面；检索失败须在答复中说明，不能用模型记忆补齐“今日资讯”。

即时启动在同一事务中保存请求、对话和首轮消息，再进入后台队列。首轮冻结北京时间、研究截止日、模型、推理档位及完整技能快照和哈希。网络重试使用原 `request_id`，重用同一对话和任务；已完成、失败或停止的任务不会因重放请求自动重跑。排队前中断可用相同请求恢复，跨日恢复仍保留原截止时间。

后续扩展由维护者在 `apps/api/app/research_assistants.py` 的 `BUILTINS` 注册 `AssistantDefinition`，并在 `apps/api/app/skills/<skill>/SKILL.md` 提供方法、来源要求和输出规范。即时助手配置 `launch_mode="immediate"`、按钮文案和 `default_prompt`（支持 `{as_of_date}`），更新 `revision`，沿用统一启动接口；现有客户端按目录元数据呈现。当前即时任务仅支持无参数启动，`input_schema` 是扩展契约；增加参数时需同步实现服务端校验、请求哈希与界面输入。上线前覆盖目录、幂等重试、冻结快照和失败恢复测试，用户端继续保持点击即用。
